# Slei EinUI Sitewide Refactor Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the Slei desktop UI foundation around EinUI dark-first liquid glass across tokens, primitives, shared components, pages, icons, notifications, dependencies, and audit tests.

**Architecture:** This is a one-shot sitewide migration with layered execution. First lock dependency and audit guardrails, then replace design tokens and primitives, then migrate shared components and pages, and finally verify the app with unit, audit, typecheck, lint, and manual UI checks. Business data flow remains daemon-backed; React stays a presentation shell.

**Tech Stack:** React 19, Vite, Tauri, Tailwind CSS v4, shadcn CLI, EinUI registry, Radix independent packages, framer-motion, lucide-react, Vitest, jsdom.

---

## Scope Check

The user explicitly chose a one-shot sitewide migration rather than phased sub-projects. Keep this as one plan, but execute it in layered commits so each commit is testable and reviewable.

Do not change daemon business logic, SQLite persistence, channel routing, task source/card semantics, or production data rules. If a test fails because UI data behavior changed, treat that as a regression unless the spec explicitly requires it.
